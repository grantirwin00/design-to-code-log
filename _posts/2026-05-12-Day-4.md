# Day 4: Craft Gets Smarter

Picking up where Day 3 left off. Craft was live and functional -- a clean single-file tool with seven learning buckets, a working admin panel, and a Vercel deploy pipeline. Today's session was about depth: turning a well-designed list into a real learning tool.

Four meaningful upgrades shipped.

---

## Guided Learning Paths

The biggest change. Flat resource lists are gone. Each bucket now has named steps -- "Build Your Foundation," "Learn the Methods," "Synthesize & Communicate," "Integrate Into Practice" -- that group resources into a meaningful progression from foundational to applied.

The bucket detail page was rebuilt around a two-column CSS Grid layout with a sticky "Why It Matters" sidebar that follows you as you scroll. A Recommended Approach section inside the sidebar adds practical guidance on how to actually work through the material.

Progress tracking is now persisted to `localStorage` using a `{stepNum}-{resourceIndex}` key schema. Checkmarks survive a page refresh. Clicking a resource checkbox expands an inline form prompting for one takeaway before marking it complete -- a small forcing function that makes the learning stick.

---

## Layout Breathing Room

The content layer was sitting at roughly 60-70% of a typical desktop viewport. Functional, but tight for a tool designers are meant to spend real time in. Max-width bumped from `1200px` to `1440px` across all pages -- more room without going full-bleed.

---

## Admin Panel Polish

A small but satisfying fix: the resource count column in the admin bucket list was misaligned due to variable label widths. Locked to a fixed `135px` width with centered text -- consistent at any resource count.

---

## GitHub-Backed CMS

This was the main event. The problem: admin edits only saved to the browser's `localStorage`, making changes invisible to every other user.

The solution is a lightweight CMS backed entirely by the GitHub repo:

- `data.json` lives in the repo as the shared source of truth, fetched at runtime by every visitor
- A Vercel serverless function (`/api/publish.js`) acts as a secure proxy -- the GitHub token lives in environment variables, never exposed to the client
- When an admin submits changes, the function creates a new branch (`cms-update-{timestamp}-{author}`), commits the updated `data.json`, and opens a pull request targeting a dedicated `cms` staging branch
- A floating CMS banner sits below the admin nav with two states: Pending (blue) shows change count with Cancel and Submit actions; Submitted (green) confirms the PR was created with a direct "View PR →" link
- Submitting opens a modal asking for the author's name -- every content change is signed

No third-party CMS. No database. No recurring costs. The entire content pipeline runs through GitHub.

---

## Fixed Navigation

All three navigation bars -- public home, bucket detail, and admin -- converted to `position: fixed`. The nav stays pinned as you scroll, consistent with the CMS banner behavior. Content padding adjusted throughout to compensate.

---

## Where Craft Stands

Two sessions in, the full stack looks like this:

- **Vanilla JS / HTML / CSS** -- no framework, no build step
- **Vercel** -- hosting and serverless functions
- **GitHub** -- content store, review workflow, and deploy trigger
- **Zero third-party services**

The learning paths give designers a clear on-ramp into any focus area. The CMS gives team leads full content control without touching code. Changes go through PR review before going live. And it all still fits in a single file.
